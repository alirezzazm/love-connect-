# دعوت به قرار

یک وب‌اپ کوچک: برای هر نفر یک **لینک اختصاصی** می‌سازی و می‌فرستی. آن طرف
صفحه‌ای باز می‌شود که می‌پرسد «با من میای بریم سر قرار؟» — و دکمهٔ **نه** از
نشانگر موس (و از انگشت، روی موبایل) فرار می‌کند و اجازهٔ کلیک نمی‌دهد. بعد از
«بله»، چند سؤال می‌آید: کجا برویم، چه بخوریم، چه روز و ساعتی. در پایان خلاصهٔ
انتخاب‌هایش را می‌بیند و **جواب‌ها در پنل ادمین برای تو ثبت می‌شود**.

## امکانات

**صفحهٔ دعوت — `/d/<slug>`**

- سؤال اول با دکمهٔ «نه» فراری
  - روی دسکتاپ: با نزدیک شدن نشانگر (تا ۱۱۰ پیکسل) جا خالی می‌دهد
  - روی موبایل: با `pointerdown` می‌پرد، **پیش از آن‌که رویداد کلیک شلیک شود**
  - هر بار فرار، یک جملهٔ تشویقی عوض می‌شود و دکمهٔ «بله» کمی بزرگ‌تر می‌شود
- سؤال‌های گزینه‌ای (کجا برویم؟ چه بخوریم؟ …) با نوار پیشرفت و امکان برگشت
- سؤال روز و ساعت با تقویم و ساعت، که به تاریخ شمسی نمایش داده می‌شود
- صفحهٔ پایانی: خلاصهٔ انتخاب‌ها، پیام پایانی تو، و قلب‌های شناور

**پنل ادمین — `/admin`**

- فهرست همهٔ دعوت‌ها با وضعیت هرکدام: *باز نشده / دیده شده / جواب داده / غیرفعال*
- ساخت دعوت تازه، کپی لینک، پیش‌نمایش
- ویرایش کامل: اسم‌ها، متن سؤال اول، پیام پایانی، و سؤال‌ها و گزینه‌هایشان
  (اضافه/حذف سؤال، اضافه/حذف گزینه، تغییر نوع سؤال)
- دیدن جوابِ هر نفر، تعداد بازدید لینک، و اینکه **چند بار سعی کرده «نه» را بزند**
- فعال/غیرفعال کردن لینک، و حذف دعوت

## استک

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 ·
Prisma + SQLite · jose (نشست JWT در کوکی `httpOnly`)

## راه‌اندازی

```bash
npm install
cp .env.example .env      # مقادیر داخلش را پر کن
npm run setup             # ساخت دیتابیس
npm run dev               # http://localhost:3000
```

سپس برو به `/admin`، وارد شو و اولین دعوت را بساز.

### متغیرهای محیطی

| متغیر | توضیح |
| --- | --- |
| `DATABASE_URL` | مسیر دیتابیس SQLite، مثلاً `file:./dev.db` |
| `ADMIN_USERNAME` | نام کاربری ورود به پنل |
| `ADMIN_PASSWORD` | رمز ورود به پنل |
| `AUTH_SECRET` | کلید امضای کوکی نشست، حداقل ۳۲ کاراکتر — `openssl rand -base64 32` |
| `NEXT_PUBLIC_SITE_URL` | آدرس اصلی سایت، برای ساختن لینک دعوت در پنل |

> فایل `.env` در `.gitignore` است و هیچ‌وقت نباید commit شود. روی سرور،
> این متغیرها را در تنظیمات محیط همان‌جا وارد کن.

## پابلیش

```bash
npm run build
npm start                 # روی پورت ۳۰۰۰
```

نکته‌های استقرار:

1. `NEXT_PUBLIC_SITE_URL` را روی دامنهٔ واقعی بگذار تا لینک‌هایی که پنل می‌سازد درست باشند.
2. `AUTH_SECRET` را حتماً عوض کن؛ مقدار محلی را روی سرور استفاده نکن.
3. حتماً **HTTPS** داشته باش — کوکی نشست در حالت production فقط روی HTTPS ارسال می‌شود.
4. فایل دیتابیس (`prisma/dev.db`) باید روی دیسک ماندگار باشد، نه فایل‌سیستم موقتی.
   اگر روی سرویسی مثل Vercel پابلیش می‌کنی، SQLite کار نمی‌کند و باید در
   `prisma/schema.prisma` به PostgreSQL سوییچ کنی.

## امنیت

- ورود ادمین با مقایسهٔ constant-time انجام می‌شود تا رمز با اندازه‌گیری زمان لو نرود.
- نشست، یک JWT امضاشده در کوکی `httpOnly` + `sameSite=lax` است.
- `middleware.ts` هم صفحه‌های `/admin/*` و هم `/api/invites*` را می‌بندد؛ بدون
  نشست معتبر، API پاسخ ۴۰۱ می‌دهد.
- هنگام ثبت جواب، **متن سؤال از دیتابیس خوانده می‌شود نه از ورودی کاربر**، تا کسی
  نتواند با دستکاری درخواست، متن دلخواه در پنل ادمین بنشاند.

## ساختار

```
prisma/schema.prisma        Invite / Question / Response
src/
├── middleware.ts           محافظت از /admin و /api/invites
├── lib/
│   ├── session.ts          JWT و کوکی — Edge-safe، فقط jose
│   ├── credentials.ts      بررسی نام کاربری و رمز (Node، node:crypto)
│   ├── validate.ts         اعتبارسنجی ورودی فرم دعوت
│   ├── defaults.ts         متن و سؤال‌های پیش‌فرض + ساخت slug
│   ├── site.ts             ساخت آدرس کامل دعوت
│   └── db.ts               نمونهٔ Prisma
├── components/
│   └── RunawayNo.tsx       دکمهٔ «نه» فراری
└── app/
    ├── page.tsx            صفحهٔ معرفی
    ├── d/[slug]/           صفحهٔ دعوت + InviteFlow
    ├── admin/login/        صفحهٔ ورود
    ├── admin/(panel)/      فهرست، ساخت، جزئیات و ویرایش
    └── api/                auth، invites، ثبت جواب
```

`admin/(panel)` یک route group است: صفحهٔ ورود بیرون آن می‌ماند تا هدر و
دکمهٔ خروجِ پنل رویش نیفتد.
